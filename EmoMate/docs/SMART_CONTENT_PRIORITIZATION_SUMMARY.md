## 📋 项目概述

### 核心目标

让AI回复**既简洁又完整**,实现以下目标:
1. ✅ **句子完整性** - 不被截断,不说半句话
2. ✅ **重点优先** - 核心信息先说,次要信息自动过滤
3. ✅ **自然交流** - 根据问题复杂度灵活调整长度
4. ✅ **过滤废话** - 删除"还有"、"然后"等无用连接词

### 核心理念

**删除废话,不是删除实质内容**

```
❌ 错误理念: "强制1-2句话,越短越好"
✅ 正确理念: "简单问题1-2句,复杂问题2-3句说清楚"

删除的是:
- "还有味增汤~" (次要信息)
- "然后还做了..." (空洞连接)
- "你说什么?" (反问拖延)
- "嗯…" (纯语气词)

保留的是:
- "吃了寿司~是三文鱼的~" (有价值补充)
- "去了公园~天气很好~" (完整描述)
- "你吃了吗?" (自然互动)
```

## 🏗️ 技术架构

### 三层防护机制

```
┌─────────────────────────────────────────────┐
│ Layer 1: AI生成层 (System Prompt优化)       │
│ - 引导AI按重要性排序生成内容                │
│ - 第1句=核心答案, 第2-3句=有价值补充        │
│ - 禁止: 纯语气词、反问拖延、空洞废话        │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│ Layer 2: 流式处理层 (SmartSentenceBuffer)   │
│ - 实时检测完整句子                          │
│ - 计算每句话的重要性评分 (0-1)              │
│ - 智能过滤低价值句子                        │
│ - 第1句: 必须播放 (除非是纯语气词)          │
│ - 第2-3句: 根据重要性和长度限制决定         │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│ Layer 3: 后置验证层 (validateResponse)      │
│ - 确保不超过字符限制                        │
│ - 保证句子完整性 (优先保留完整句子)         │
│ - 最终安全检查                              │
└─────────────────────────────────────────────┘
                    ↓
              TTS播放给用户
```

## ⚙️ 当前配置参数

### SmartSentenceBuffer 配置

| 对话类型 | 最大字符 | 最大句子 | 重要性阈值 | 适用场景 |
|---------|---------|---------|-----------|---------|
| **simple** | 60 | 2 | 0.5 | 问候、确认 |
| **normal** | 100 | 3 | 0.5 | 日常聊天 |
| **detailed** | 180 | 4 | 0.4 | 解释说明 |
| **storytelling** | 300 | 6 | 0.3 | 讲故事 |

### 重要性评分规则

```typescript
基础分: 0.5

加分项:
+ 核心关键词 ('是','有','吃了','做了'等): +0.2
+ 正常问句 ('你吃了吗?','要不要?'): +0.15

扣分项:
- 纯语气词 ('嗯…','诶?'): 直接降到0.1
- 句子过长 (>25字): -0.3
- 补充连接词 ('还','然后','另外'): -0.2
- 例举词 ('比如','例如'): -0.25
- 解释短语 ('因为','所以','其实'): -0.2
- 反问拖延 ('你说什么?','你问?'): -0.3
- 内容过短 (<3字符): -0.3

最终分数: 限制在 [0, 1] 范围
```

## 🎯 核心System Prompt规则

### 禁止的回答方式 ❌

```markdown
1. 纯语气词
   ❌ "嗯…"
   ❌ "诶？"
   ❌ "让我想想~"

2. 反问拖延
   ❌ "你说的是什么呀?" (用户已经说清楚时)
   ❌ "你问午饭吗?" (明知故问)
   ❌ "怎么了吗?" (空洞反问)

3. 空洞客套
   ❌ "好的好的~"
   ❌ "知道啦~"
   ❌ "嗯嗯~" (没有实质回应)

4. 无关废话
   ❌ "然后还有..."
   ❌ "另外..."
   ❌ "以及其他的..."
```

### 推荐的回答方式 ✅

```markdown
1. 简单问题直接答 (1-2句)
   ✅ "今天不错呢~"
   ✅ "吃了寿司~"
   ✅ "我很好呢~"

2. 复杂问题详细答 (2-3句)
   ✅ "今天天气很好~去了公园~玩得很开心~"
   ✅ "因为很有趣呢~而且能学到东西~"

3. 不确定时澄清 (不是拖延)
   ✅ "你是说午饭还是晚饭?" (澄清问题)
   ❌ "你问什么呀?" (拖延)

4. 自然话题延续
   ✅ "吃了寿司~你呢?"
   ✅ "今天很不错~你今天怎么样?"
```

## 🔧 如何调优参数

### 情况1: AI回复仍然太长

**症状**: 经常说3-4句,感觉啰嗦

**解决方案**:
```typescript
// 方法1: 降低最大句子数
// 文件: src/utils/smartSentenceBuffer.ts:318-323
case 'normal':
  return {
    maxCharacters: 100,
    maxSentences: 2,  // 改回2 (当前3)
    importanceThreshold: 0.5
  };

// 方法2: 提高重要性阈值
case 'normal':
  return {
    maxCharacters: 100,
    maxSentences: 3,
    importanceThreshold: 0.6  // 0.5 -> 0.6 (更严格)
  };

// 方法3: 在System Prompt中强调
// 文件: src/constants/ai.ts:117-120
1. 直接回答核心问题 - 越简洁越好
2. 一般1-2句话,特殊情况才说3句
```

### 情况2: AI回复太简短,答不清楚

**症状**: 复杂问题只回答1句,信息不完整

**解决方案**:
```typescript
// 方法1: 提高最大句子数
case 'normal':
  return {
    maxCharacters: 100,
    maxSentences: 4,  // 3 -> 4
    importanceThreshold: 0.5
  };

// 方法2: 降低重要性阈值
case 'normal':
  return {
    maxCharacters: 100,
    maxSentences: 3,
    importanceThreshold: 0.4  // 0.5 -> 0.4 (更宽松)
  };

// 方法3: 增加字符限制
case 'normal':
  return {
    maxCharacters: 120,  // 100 -> 120
    maxSentences: 3,
    importanceThreshold: 0.5
  };
```

### 情况3: 仍有反问拖延

**症状**: AI还会说"你说什么?"、"怎么了吗?"

**解决方案**:
```typescript
// 文件: src/utils/smartSentenceBuffer.ts:302-307
// 添加更多反问拖延模式
const delayingQuestions = [
  /^(你说|你是说|你问|你指|你想|你觉得|你认为)/,
  /^(什么|怎么|为什么)[？吗呢]?$/,
  /^诶[？吗呢]/,
  /^(是吗|真的吗|这样啊)[？~]*$/,
  // 新增:
  /^你指的是/,
  /^你的意思是/,
  /^怎么了[吗？]/,
];

// 或者加大惩罚力度
if (delayingQuestions.some(...)) {
  score -= 0.5;  // 0.3 -> 0.5 (更重惩罚)
}
```

### 情况4: 有用的问句被过滤

**症状**: "你吃了吗?"这类自然互动也被过滤了

**解决方案**:
```typescript
// 优化反问检测正则表达式,更精确
const delayingQuestions = [
  /^你(说|是说|问)的?(是)?什么/,  // 更精确
  /^(什么|怎么|为什么)啊?[？吗呢]?$/,
  /^你指的?是?[什么谁]/,
];

// 确保自然问句得到加分
const naturalQuestions = [
  /吃了吗/,
  /要不要/,
  /好不好/,
  /是不是/,
];
if (naturalQuestions.some(p => p.test(sentence))) {
  score += 0.2;  // 额外加分
}
```

### 情况5: 废话仍然没被过滤

**症状**: "还有..."、"然后..."这类仍然出现

**解决方案**:
```typescript
// 文件: src/utils/smartSentenceBuffer.ts:278-280
// 增加补充连接词列表
const supplementWords = [
  '然后', '还', '另外', '此外', '而且',
  '以及', '同时', '并且',
  // 新增:
  '接着', '随后', '紧接着', '后来',
];

// 或者加大惩罚
if (supplementWords.some(w => sentence.includes(w))) {
  score -= 0.3;  // 0.2 -> 0.3 (更重惩罚)
}
```

## 🐛 已知问题和限制

### 1. 对话类型检测不够精确

**问题**: 有时候会把复杂问题判断为simple,导致回复太短

**影响**: 中等

**临时解决方案**:
- 手动调整simple类型的maxSentences从2改为3
- 或降低simple的importanceThreshold从0.5改为0.4

**根本解决**: 需要优化detectConversationType()函数

### 2. 某些有价值的补充仍被过滤

**问题**: 包含"还"字但有价值的句子也被过滤

**示例**: "还很好吃呢~" 被过滤 (因为包含"还"字)

**影响**: 低

**解决方案**:
```typescript
// 更精确的"还"字检测
if (/^还有/.test(sentence)) {  // 只过滤"还有..."开头
  score -= 0.2;
}
// 而不是: if (sentence.includes('还'))
```

### 3. 首句仍可能是纯语气词

**问题**: 虽然被检测到但作为第1句仍被播放(极少数情况)

**影响**: 极低

**说明**: 当前已在shouldPlay()中增加了第1句的纯语气词检测,但System Prompt应该已经避免了这种情况
